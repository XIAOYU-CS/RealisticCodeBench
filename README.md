# RealisticCodeBench

RealisticCodeBench is a **multilingual code generation benchmark** built from **real-world GitHub code** that was labeled as generated by ChatGPT or Copilot. The benchmark is designed to evaluate whether large language models can solve the kinds of **function- and class-level programming tasks** that developers plausibly ask LLMs to generate in daily work.

This release follows the benchmark description in "RealisticCodeBench: Towards More Realistic Evaluation of Large Language Models for Code Generation" by Xiao Yu et al. The paper reports **376 programming problems** across **Python, JavaScript, TypeScript, Java, and C++**, with each available language version containing an **input prompt/signature**, a **reference solution**, and **tests**.

## Contents

```text
tasks/
  t1/ ... t376/              Benchmark tasks.
envs/                        Language runner workspaces and dependency manifests.
run_task.sh                  Unified local runner.
task_standard_format.md      Task file layout contract.
metadata/RealisticCodeBench_detail_info.xlsx
```

The **internal pruning archive** and **machine-local environment file** are intentionally not included in this release copy.

## Dataset Size

| Language | Complete tasks |
|---|---:|
| Python | **361** |
| JavaScript | **346** |
| TypeScript | **343** |
| Java | **307** |
| C/C++ | **323** |
| Total task roots | **376** |

A task root can contain fewer than five language versions. This is expected: the paper notes that some tasks are language-specific when a direct translation would be unnatural or depend on ecosystem-specific types or operations.

## Task Layout

Each task has one root source file and zero or more language directories:

```text
tasks/t<ID>/
  origin.py | origin.js | origin.ts | origin.c | origin.cpp | Original.java
  python/
  javascript/
  typescript/
  java/
  c&cpp/
```

Language file sets:

```text
python/      signature.py  answer.py|adapted.py  test.py
javascript/  signature.js  answer.js|adapted.js  test.js
typescript/  signature.ts  answer.ts|adapted.ts  test.ts
java/        Signature.java Answer.java          Tester.java
c&cpp/       signature.cpp answer.cpp|adapted.cpp test.cpp
```

The **`signature` file** is the model-facing prompt and function/class contract. The **`answer` or `adapted` file** is the reference implementation. The **`test` file** is the executable correctness oracle.

## Running Tests

Run one task:

```sh
sh run_task.sh t139
```

Run multiple tasks:

```sh
sh run_task.sh t139 t140
sh run_task.sh '[t139,t140]'
sh run_task.sh '["t139","t140"]'
```

The runner creates **`envs/.env` automatically** if it is missing. Edit that generated file only for local tool paths.

Language runners:

- Python: concatenates `answer.py` and `test.py` and executes them with the configured Python interpreter.
- JavaScript: uses Jest with the JavaScript environment under `envs/javascript`.
- TypeScript: uses Jest/ts-jest with the TypeScript environment under `envs/typescript`.
- Java: uses Maven/JUnit under `envs/java`.
- C/C++: uses the included Catch2-based C++ environment under `envs/c&cpp`.

JavaScript and TypeScript dependencies are installed from the included `package-lock.json` files as needed. Java dependencies are resolved by Maven from `envs/java/pom.xml`.

## Evaluation Protocol

For LLM evaluation, provide the **language-specific signature/prompt** to the model, place the generated implementation where the reference implementation normally lives, and run the corresponding tests. Aggregate pass rates per language or with **pass@k** as described in the paper.

This release includes reference implementations for reproducibility and test development. **They should not be used as model input during benchmark evaluation.**
